Module 1.2 Blog Post

Introduction

Digital systems play an important role in how organizations operate. Developing them involves more than just creating a functional system. As technology and user needs evolve, software engineers must build systems that can adapt alongside them. Understanding system development life cycles and the different approaches to system development allows for a more robust and future-proof system. This blog post explores three separate life cycle models: Linear, Iterative, and Incremental, and covers their major advantages and potential drawbacks. Additionally, I will go more in depth on why life cycle thinking is crucial in digital system development.

Systems Development Life Cycle

The systems development life cycle (SDLC) is a framework that describes the process of developing information systems. It provides a structured approach to planning, creating, testing, and deploying software applications. The SDLC consists of several phases, including requirements gathering, system design, implementation, testing, deployment, and maintenance. Each phase has specific objectives and deliverables that contribute to the overall success of the project. By following the SDLC, organizations can ensure that their software development projects are well-organized, efficient, and aligned with business goals.

Linear Life Cycle Model

The linear life cycle model, also known as the waterfall model, follows an approach where each stage of development is completed before continuing to the next. Alam et al. (2022) explain that the model consists of five main stages: communication, planning, design, construction, and deployment. Each stage is clearly defined, making the development process easier to organize.

One of the major advantages of the linear model is that it’s structured in a way that makes it easier to plan tasks, manage resources, and track progress. For example, using the university example from earlier, the linear model could help the university establish a clearer schedule for each stage of development and assign the necessary resources before development begins. This can help the university keep the project on schedule and avoid unnecessary expenses as the project progresses. However, one of the main downsides of the linear model is its lack of flexibility. Suppose a new AI tool becomes available during development that lets universities automatically generate personalized course schedules based on their student’s degree requirements and preferences. If the university wanted to incorporate this feature, they would have to significantly rework earlier stages of development, which would result in significant delays and/or increased project costs. Because of this, the linear model is less suitable for projects where the requirements are expected to change over time.

Iterative Life Cycle Model

Unlike the linear model, the iterative model allows developers to proactively improve and refine a system over time. Alam et al. (2022) explain that the model consists of four main stages: requirements, analysis, design, and coding. Instead of completing the whole development process in one sequence, developers work through multiple iterations, making improvements and addressing issues as they arise.

One major advantage of the iterative model is its flexibility. Since developers can make changes throughout the development process, it’s easier to accommodate new requirements and address feedback. Going back to the university example, if they used an iterative model, they could create an initial version of the new system for students and staff to test. Using their feedback, developers can identify problems with the registration process and work towards fixing them in future iterations. This process also supports Holt’s (2023) emphasis on understanding different needs and perspectives of stakeholders to ensure that the system meets their expectations.

One drawback is that the iterative model can take longer to complete and require more resources and funding. If the university continued making significant changes each iteration, developers would need extra time to implement and test those changes, making it more difficult to stay within the project's original budget and timeline.

Incremental Life Cycle Model

The incremental model follows an approach where a system is developed and delivered in smaller, functional parts called increments. Instead of waiting until the entire system is completed, each increment adds new features that build upon the previous version. This allows developers to prioritize essential features first and gradually expand the system’s functionality (New Line Technologies, n.d.).

One major advantage of this model is that users can begin testing and using the system before all of its features are complete. Continuing our university example, it could first release a basic version of its new course registration system that lets students search and register for classes. Later increments could introduce new features, like personalized schedule recommendations and automatic class availability alerts. This approach would allow students and staff to benefit from the essential features immediately, while also allowing developers to expand functionality based on feedback and changing requirements.

One potential drawback of this model is that integrating new features with the existing system can be a challenge. Holt (2023) emphasizes that understanding how different system elements interact is as important as understanding the elements themselves. If the university introduced automatic class availability alerts as a later increment, developers would need to ensure that this feature works correctly with the existing enrollment system before releasing it. If the alert feature and enrollment system don’t communicate properly, students could get false notifications and miss available openings for classes they might be interested in. Resolving these issues could require extra testing and development time, delaying feature releases and increasing project costs.

The Imporance of Life Cycle Thinking

All of these life cycle models emphasize the importance of decisions made during the development phase of a system, and influence its design, evolution, and long-term sustainability. When designing a system, developers should not only consider its current requirements, but also how those requirements might change in the future. This includes anticipating new technological advancements, planning for additional features as user needs change, and ensuring that different parts of a system can be changed without affecting its overall functionality. These decisions also affect how easily a digital system can evolve after initial development. For example, a well-designed banking application could add biometric authentication without needing to redesign its existing login system, which would save both time and resources while allowing the application to adapt to new security technologies as they come out. By designing a system around life cycle thinking, developers can prevent unnecessary development costs and simplify future updates as their system evolves.

Life cycle thinking also supports sustainability by helping organizations maintain their systems over longer periods of time. This involves planning for maintenance, implementing security updates, and improving system efficiency. Not only does this help organizations reduce their long-term operational costs, but it also promotes sustainability by minimizing resource waste and reducing the need for frequent system replacements. By considering these factors, I hope I’ve communicated how vital it is for digital systems to work alongside life cycle thinking.

Module 2.2 Blog Post

Introduction

Digital systems have become an integral part of our daily lives. They help us communicate more effectively, access valuable information, and complete tasks faster. But to ensure the effectiveness of these systems, it’s crucial to consider the system’s usability. This depends on how well it can address the needs, expectations, and limitations of the people interacting with it, and even small design choices like how readable text is can drastically alter a user’s ability to accomplish their goals. In this post, I’ll discuss how memory, user habits, interface consistency, and system feedback can influence the usability of a digital system. I’ll also explore how poor design choices can create unnecessary cognitive load and use examples from the course readings, credible outside sources, and my own experiences to support my reasoning.

Memory, Mental Models, and User Interaction

When we navigate websites or applications in our day-to-day life, we rely on our past experiences to understand how certain features work. For example, take a magnifying glass icon on a website. Based on our experiences with other websites, we intuitively know this likely represents a search button. This demonstrates how memory shapes interactions with digital systems.

With that in mind, a person’s memory has limitations that must be considered. Johnson (2021) explains that a working memory can only handle a small amount of information at a time, and that it can be easy to forget important details when distractions are introduced. Imagine searching for specific information on a website, only for the website to clear your search terms once the results load. As you scan through the results, you may forget specific keywords you used once the results display, making analysis of the results have worse context. This example also highlights Tesler’s Law, which states that every digital system has unavoidable complexity that must be managed by either the system or its users (Yablonski, 2024). By keeping the original search terms available, the website can help manage this complexity and reduce the amount of information that users need to remember so they can focus more on refining their results.

Implementing this correctly requires designers to consider the mental models their audience would have already developed. Mental models are expectations that people have about how things should work based on their past experiences. Keeping our magnifying glass example from earlier in mind, clicking on a magnifying glass for it to show an animation burning out search results, similar to a magnifying glass in the sun, would not be intuitive, but having it open a search bar to be able to search through a list of options would be expected by the website’s general audience. Johnson (2021) emphasizes that recognizing familiar features is easier than having to remember how everything works. When incorporating recognizable and obvious design elements, developers and system designers can make interfaces easier and more intuitive to navigate, since people already have preconceived notions about certain design elements.

How Habits Influence Usability

Our past experiences also influence the habits we develop when using digital systems. Johnson (2021) explains that people often prefer familiar ways of completing tasks, even if more efficient alternatives exist. One example of this is how my dad copies and pastes text and files on his computer. I’ve shown him how to use the Ctrl+C and Ctrl+V keyboard shortcuts, but he still prefers right-clicking to select the copy/paste options because it’s what he’s most familiar with. This demonstrates how once we’ve become familiar with a process, repeating it requires less mental effort than learning something new. Even though keyboard shortcuts are faster, changing my dad’s habits would require more effort than continuing with what he already knows.

People also rely on familiar clues in digital systems to reduce mental effort and improve usability. Johnson (2021) describes this as information scent, where people look for words, icons, and other indicators to help guide them to their goals. For example, someone who’s trying to change their password is likely to look for a menu named “Security” or “Account Settings”, since their past experiences suggest that’s where this setting would be located. Familiar clues like this make it easier for people to find what they’re looking for without having to think too much about where to go.

Interface Consistency and System Feedback

It’s important to consider interface consistency and system feedback when designing digital systems. Interface consistency is ensuring that the design and layout of a digital system remain consistent and familiar to users. For example, using our search bar example again, users would expect to find the same search menu in different parts of the website. If the search menu suddenly went to a different corner of the website or functioned significantly differently, that could confuse users and make them spend unnecessary time learning how to navigate the same website in different ways. By keeping these elements consistent, website and app designers reduce confusion and help users navigate their systems better.

On the other hand, system feedback is the focus on communicating what happens when a user performs an action. In her article, ‘Visibility of System Status’, Harley (2018) emphasizes the importance of keeping users informed about a system’s status through feedback. For example, submitting an assignment through Canvas has a confetti animation on submission. If the submission didn’t have any indication of whether it was successful, you would have no idea if the assignment was actually submitted, and it would lead to feelings of stress and uncertainty. Website and app designers need to keep this in mind and provide clear feedback in the form of confirmation messages, progress bars, or other visual indicators to communicate to users what’s going on. System feedback ultimately makes digital systems easier to use and gives users more confidence in their interactions.

Poor Design Increases Cognitive Load

While interface consistency and system feedback can improve usability, poor design choices can increase unnecessary cognitive load. One example of this is change blindness. This occurs when users don’t notice changes in their environment because they're focused elsewhere (Johnson, 2021). For example, I commonly use OBS Studio to record commentary videos for my YouTube channel. Sometimes, when I adjust my recording settings, my audio input device automatically switches to my webcam’s microphone without me noticing. I’ve had to rerecord entire commentaries because of this, since OBS Studio doesn’t provide a clear indicator when your audio input device changes. As a result, I’ve grown used to constantly checking what audio input device is being used even if I haven’t changed it. By adding a clear notification whenever the audio input device changes, OBS Studio could reduce unnecessary cognitive load by letting users focus more on their recordings instead of whether the correct microphone is being used. This also reflects Tesler’s Law, since OBS Studio would take more responsibility for ensuring users are using their preferred microphone (Yablonski, 2024).

Another poor design choice that can increase cognitive load is using text that’s difficult to read. Johnson (2021) highlights this by showing an older version of Apple’s App Store. In this example, estimated download times were displayed with dark gray text on a gray background, making it harder to see. As a result, this forced users to spend more time and mental effort trying to read basic information that should have been clearly visible. To avoid this, website and app designers should ensure that text contrasts enough with the background to make important information easy and effortless to read. This is supported by the World Wide Web Consortium (W3C, 2026), which recommends a minimum contrast ratio of 4.5:1 between normal-sized text and the background to improve readability, especially among older individuals or people with poor vision.

Conclusion

In conclusion, a digital system’s usability goes beyond just making it functional. It also considers the memory, mental models, habits, and expectations of its users. Understanding principles like information scent and change blindness can help system designers identify usability problems and create interfaces that align better with their audiences’ needs. By reducing a user’s cognitive load, system designers can create a more intuitive user experience that requires less mental effort and helps users achieve their goals faster.
